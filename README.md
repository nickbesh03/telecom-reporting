# Контур связи — telecom-reporting

Адаптируемый MVP для команды из пяти человек, кейс №2 хакатона: отчётность о работе сотовой подвижной сети. **Полное ТЗ ещё неизвестно.** Этот проект — проверяемая стартовая основа, а не заявление о выполнении требований соревнования.

## Что можно показать

- Русский адаптивный интерфейс: обзор, станции, суточные показатели, импорт/экспорт.
- Создание, изменение, удаление станций и показателей; понятные ошибки и защита от повторов.
- Фильтры по периоду, региону и станции; таблица с постраничным просмотром.
- Трафик, взвешенная по вызовам доля обрывов, доступность по загруженным записям, график и региональная сводка.
- Атомарный CSV-импорт с указанием ошибочных строк, CSV-экспорт всего результата фильтра, печать обзора в PDF средствами браузера.
- 6 вымышленных станций × 14 дней (15–28 октября 2026), 84 записи; повторный запуск сохраняет данные.
- REST API, машиночитаемое описание `/openapi/v1.json`, интеграционные тесты SQLite/MariaDB, браузерная проверка, CI.

Стек: C# / ASP.NET Core 10, EF Core 9 + Pomelo, MariaDB 11.4, Vue 3, Vite, Docker Compose. EF Core 9 выбран для совместимости с провайдером MariaDB. SQLite используется только для локальной проверки без Docker.

## Запуск с MariaDB — основной способ

Нужны Git и работающий Docker Desktop в режиме Linux containers. На Windows запустите Docker Desktop и дождитесь готовности движка.

```powershell
git clone https://github.com/nickbesh03/telecom-reporting.git
cd telecom-reporting
Copy-Item .env.example .env
# Откройте .env и замените оба демонстрационных пароля.
docker compose up --build -d
```

Откройте **http://localhost:8080**. Первая сборка скачивает зависимости и может занять несколько минут. Проверка API: http://localhost:8080/api/health. База не публикует порт наружу, приложение слушает только этот компьютер.

```powershell
docker compose logs --tail 80
docker compose down
```

Данные лежат в Docker volume `network-data` и сохраняются при `down`. `docker compose down -v` **удалит всю базу**, используйте только для осознанного сброса демо. `EnsureCreated` создаёт исходную схему, но не обновляет существующую: после изменения модели подготовьте EF migrations либо сбросьте исключительно тестовую базу. В рабочей системе нужен миграционный процесс.

## Быстрая локальная проверка без Docker

Нужны .NET SDK 10 и Node.js 24. Из корня проекта, окно 1:

```powershell
$env:Database__Provider="Sqlite"
$env:ConnectionStrings__Network="Data Source=telecom.db"
$env:ASPNETCORE_URLS="http://127.0.0.1:5080"
dotnet run --project backend --no-launch-profile
```

Окно 2:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте адрес Vite, обычно **http://localhost:5173**. Прокси направит запросы на API. SQLite-файл находится в каталоге backend. В Linux/macOS задайте те же переменные через `export`. Не оставляйте `Database__Provider=Sqlite`, если переходите на MariaDB.

## Проверки

Из корня:

```powershell
dotnet test tests
cd frontend
npm ci
npm test
npm run build
npx playwright install chromium
npx playwright test
```

Playwright сам запускает API и интерфейс. Использует отдельный `e2e.db` с синтетическими данными. Для полностью чистого повторения удалите этот тестовый файл при остановленном API.

MariaDB: переменная `TEST_MARIADB` должна содержать connection string **отдельной пустой тестовой базы**. Затем `dotnet test tests`. Тест создаёт и изменяет данные. В CI автоматически выполняются обе базы, браузерный сценарий и сборка/запуск Docker Compose. Смотрите вкладку **Actions → Verify MVP**, зелёный статус относится к конкретному коммиту.

## CSV

Образец: [samples/observations.csv](samples/observations.csv). Формат фиксированный, UTF-8 с необязательным BOM; разделитель `,`, десятичная точка, дата ISO `yyyy-MM-dd`. Коды станций — латиница/цифры/дефис/подчёркивание. Поля не содержат запятых или кавычек, общий RFC CSV с многострочными ячейками не поддерживается.

```csv
stationCode,date,trafficGb,calls,droppedCalls,downtimeMinutes
BS-001,2026-10-29,250.5,1200,9,5
BS-003,2026-10-29,190,900,11,30
```

До 1 МБ / 5000 строк. Станции создаются заранее. Повтор пары станция–дата в файле или в базе отменяет импорт целиком. Импорт добавляет записи и не заменяет существующие. Для изменения используйте редактор. Экспорт учитывает **применённые** фильтры, выгружает все строки, независимо от страницы таблицы. Итоговый отчёт можно сохранить в PDF через «Обзор» → Ctrl+P → «Сохранить как PDF».

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка подключения базы |
| GET/POST | `/api/stations` | Справочник / создание |
| PUT/DELETE | `/api/stations/{id}` | Изменение / удаление без связанных показателей |
| GET/POST | `/api/observations` | Список / создание |
| PUT/DELETE | `/api/observations/{id}` | Изменение / удаление |
| GET | `/api/report` | Итоги, динамика, группировка по регионам |
| GET | `/api/export` | CSV |
| POST | `/api/import` | Сырое тело `text/csv`, не multipart |

Фильтры GET observations/report/export: `from`, `to`, `region`, `stationId`; даты включительно. Страницы только observations: `page=1&pageSize=50`, максимум 200. Ошибки — HTTP 400, 404 или 409; ошибки валидации содержат `detail`. Swagger UI не включён, JSON OpenAPI доступен отдельно.

## Что принято условно

Единица учёта — одна станция за календарные сутки, 1440 минут. Трафик измеряется в ГБ; вызовы и обрывы — целые неотрицательные числа, обрывы не превышают вызовы. Доступность = `100 × (1 − сумма простоя / (число записей × 1440))`. Доля обрывов = `100 × сумма обрывов / сумма вызовов`. При нулевом знаменателе API возвращает 0; при пустом отчёте записей 0, интерфейс сообщает об отсутствии данных. Пропущенные станция-дни **не считаются нулевым простоем** и не входят в знаменатель. Эти формулы не являются утверждёнными отраслевыми KPI. Порог цветовой подсветки 99% — исключительно демонстрационный.

Нет авторизации, ролей, журнала действий, фоновых заданий, универсального Excel-импорта и нормативных форм. Стенд предназначен для синтетических данных на локальном компьютере. Для общего серверного доступа сначала нужны авторизация, HTTPS, ограничение запросов, резервирование, миграции и согласование требований.

## Где менять после получения ТЗ

`backend/Domain.cs` — сущности, правила, демонстрационные данные; `backend/Endpoints.cs` — API, отчёты, CSV; `frontend/src/App.vue` — экраны; `frontend/src/style.css` — оформление; `tests/ApiTests.cs` — сквозные проверки; `compose.yaml` — запуск. Отдельные сервисы и слои добавляйте при росте сложности, сейчас проект намеренно небольшой.

Сначала выпишите требования в `docs/REQUIREMENTS.md`, согласуйте поля/единицы/формулы и критерии проверки; затем измените модель, миграции, API, интерфейс и тесты вместе.

## Работа команды и двух компьютеров

Владелец приглашает участников через Settings → Collaborators: публичность позволяет читать код, но не даёт посторонним права записи. На каждом компьютере клонируйте один репозиторий и установите инструменты. Не пересылайте папки с кодом между компьютерами.

Каждая задача — отдельная ветка `feature/короткое-имя`, затем Pull Request → проверка Actions → просмотр другим участником → merge в main. Перед началом `git switch main` и `git pull`, после завершения commit и push. На другом компьютере сначала заберите изменения. Не редактируйте одну ветку одновременно на двух компьютерах без синхронизации. Не используйте force push в main. `.env`, базы и папки сборки не отправляются в Git.

Распределение на 5 человек: 1) требования/сценарий показа и координация, 2) модель и база, 3) API/импорт/отчёты, 4) интерфейс, 5) тесты/запуск/интеграция. Один участник не обязан выполнять роль один: главное — понятный владелец каждой задачи и проверка чужих изменений.

## Сценарий показа за 3 минуты

1. Откройте обзор: 84 записи, 33 222 ГБ; объясните происхождение демоданных.
2. Выберите Север → Применить: в отчёте 2 станции; покажите простой и динамику.
3. Создайте станцию, добавьте суточную запись, измените фильтр на её дату.
4. Загрузите образец CSV; повторная загрузка покажет конфликт без дублирования.
5. Выгрузите CSV, откройте Actions и покажите тесты. Перезапустите приложение и убедитесь, что записи сохранились.
